# Bounded pnpm version and layout matrix

## Approval and frozen inputs

The owner authorized local development of a reproducible compatibility matrix:
at most six exact stable producers, 64 MiB total official acquisition response
bytes, 32 pnpm invocations, 600 seconds of generation and 512 MiB private scratch.
Existing tools may be reused only after archive revalidation and fresh safe
extraction. No global installs, real-project scans, advisory acquisition, native CI,
publication, release changes or installed-binary replacement are authorized.

The official stable registry tags and pinned metadata select:
**9.0.0, 9.15.9, 10.0.0, 10.34.9, 11.28.9 and 12.18.0**. The first two majors have
floor/latest anchors; later majors use their current exact stable tag anchors,
not next/prerelease tags. These are sample anchors, not proof of every patch.

Initial preparation stopped before execution when the pnpm12 wrapper lacked the
older standalone LICENSE/JS entry layout. Its distribution uses a separate native
package. The owner additionally approved the exact official
`@pnpm/exe.linux-x64@12.18.0` within the same original budgets, with bytes and notices
verified and **no install.js or automatic acquisition**. The wrapper's BSD2 notices
and matching native package's MIT text are retained externally. This preparation
failure is preserved, not relabeled as completed execution. pnpm11 uses its actual
published `.mjs` entry, not an assumed `.cjs` path. Existing Node version/hash and
all executable/archive/license hashes are bound before use.

## Matrix and implementation boundary

Each producer reserves one version query and four owned inert installation cases:
isolated copy, hoisted copy, distinct peer-context copy and forced hardlinks.
Each runs with scripts disabled, readonly tools, private PID/network namespaces,
owned loopback registry, scratch/network/exterior-canary controls and confirmed
child reap/group cleanup. Failures and unsupported formats remain named rows;
there are no silent substitutes, retries, copied hardlinks or reset ledgers.

Preserve original lock/manifests, raw link targets and actual hardlink multiplicity
in data-only recipes. Replay is not a producer execution, and Linux producer
observations are not native Windows/macOS or release qualification. Record exact
format, layout, outcome and evidence separately from version-string recognition.

Extend shared `packageManager` hint recognition only when the produced lock format
and bounded actual scanner cases justify it. Keep `pnpm` / `pnpm@lockfile-9`
interpretation separate from a concrete producer identity, retain refusal outside
the admitted boundary and test explicit/family/auto selection without broadening
saved policy/source grants. Unsupported formats/semantics must remain incomplete.

The current installed scope stays unchanged: active contained stable single-link
manifests, exact PNPM store shape, candidate-only indeterminate correspondence,
selected-lock/native witnesses, all three mandatory gaps and expected exit3.
No hardlink allowance, workspace traversal, source authentication, advisory lookup,
strong lock-to-instance binding, integrity or exception authority is introduced.

## Acceptance

Use RED/GREEN boundary tests, all captured real recipe replays, actual owned CLI
terminal/JSON/SARIF, equal local/portable counts, unchanged-input fingerprints and
privacy. Run root/vet, relevant races, probe checks and bilingual documentation
parsers. Publish a truthful exact-anchor/layout table with refusals and limitations;
keep original failures and acquisition/invocation reservations in external receipts.
This contract is not a completed-results claim. Work remains local and does not
retroactively alter the already published v0.2.0-alpha.1 artifacts.
