# Whole installed integrity accounting (unreleased)

Operational schema remains **1.8**. Historical builders and policy pins retain
their authority contracts. This increment completes only the integrity accounting
obligation for supported, positively closed npm/Bun installed inventories. It does
not complete native/platform qualification, reference authority, advisory source/index
completeness or lifetime resource observation; aggregate operational exits remain
subject to those separate gates and `130 > 2 > 3 > 1 > 0`.

## Positive predicate

The parent joins the independently admitted original inventory to each compact
private native comparison receipt. All selected references and all actual installed
instances must have a unique corresponding endpoint. The join checks original
selected-lock claims, installed manifest bytes/identity, directory metadata receipt,
physical location, reference selection, actual verified catalog binding/digest and
record comparison digest. The actual content snapshot's own manifest receipt
must also match the retained inventory manifest bytes; a change between collection
and comparison withholds completion without losing drift. Counts, observation numbers, child completion bits and
optional changed-file policy material cannot substitute for these joins.

Default portable integrity-only scans carry this evidence too, with no new policy
permission or implicit reference acquisition. Complete equality has no findings;
complete drift can complete integrity while retaining findings. Missing/invalid
references, absent selected instances, extra/unmapped instances, unreadable/unstable
or ambiguous ownership remain incomplete. A positively closed empty installed
scope with no selected references can complete integrity and make selected-reference
comparison not applicable. Missing evidence is never an empty scope.

Nested owners require complete native directory/manifest association and their own
comparison. Their unpublished package-manager namespaces are excluded only from
the parent instance, not from whole accounting. Overlapping published reference
content remains an ownership gap. A normal file at a package-shaped path remains
ordinary compared content, never a pruned directory owner; its existing unsupported
slot-file inventory boundary remains incomplete. Links, generic shared/hardlinked
stores, workspaces and pnpm do not gain closed-scope support.

## Bounds and trust

Reuse the existing private original-byte and typed native acquisition boundary:
512 KiB cumulative original bytes, 4096 shared observation/evidence/raw-input/
material/accounting rows, 1 MiB frame and 8 MiB cumulative private encoded-byte
ceilings. Historical difference-witness lists retain their separate 4096-per-batch
cap and share the existing private bytes/channel budget. Overflow or
missing evidence withholds accounting, without dropping existing drift findings or
raising a limit. The compact catalog receipt carries binding identity and actual
observed SRI, not the full catalog or archive. Original receipts remain private;
public inventory/report JSON cannot reconstruct rendering authority.

Original bytes demonstrate consistency with the actual retained receipt bytes,
not publisher authentication or resistance to a fully malicious acquisition child
fabricating both inputs and receipts. Retained native source leases and frozen
parent report context remain required. The report is still a pre-output comparison
snapshot; actual output, source revalidation, finalization and reap failures overlay
the process decision later without rewriting previously emitted bytes.

Focused owned-fixture unit/protocol tests cover equality/drift, closed empty scope,
nested owners, unmapped/unsupported instances, missing evidence, reference/catalog,
source/metadata/instance swaps, frozen reports and privacy. These local Go tests
are not native/platform acceptance or a benchmark campaign. Full combined CLI,
root verification and independent integration review remain separate checks.
