# PackTrace v0.1.0-alpha.1

I am publishing PackTrace's first numbered **experimental prerelease**. It collects
the implemented history through the npm/Bun range expansion, rather than treating
only the last compatibility change as the release. This is not a production-qualified
release, a safety verdict, or new native-platform qualification.

## Included capabilities

- Read-only offline investigation of JavaScript dependencies, retaining declared,
  locked and physically observed installed evidence separately; bounded workspaces,
  aliases, optional absence and distinct physical copies.
- Local malicious-package/vulnerability advisory matching and prepared-reference
  integrity comparison. Version candidates remain separate from eligible findings;
  presence or a match does not prove execution, reachability or authenticated origin.
- Explicit advisory synchronization, immutable generations, independent freshness
  ages, offline import/export, retention pins and preview-bound pruning. Scan never
  silently downloads data or repairs the target.
- Pinned external policies, evidence-bound expiring exceptions, coverage/enforcement
  separation, guarded file publication, portable/local privacy, JSON and SARIF.
- Persisted per-user setup; compact package tables, semantic terminal states/colors,
  bounded original-backed advisory explanations, task-oriented help and Effect/Next
  diagnostics; complete English and Spanish user manuals.
- Stable npm 7.x–12.x and Bun 1.2.x–1.4.x **bounded interpretations**. npm 7–11 retain
  v2/v3/shrinkwrap behavior; npm12 stays v3-only and ignores shrinkwrap. Bun older
  minor families retain their own text/config limits. Legacy pinned profiles remain
  accepted; saved policy bytes/pins are not automatically rewritten.
- A small automatic one-line spinner for slow sync/import/export on supported Linux
  terminals. The parser and progress writer retain shared resource/traffic limits
  and confirmed reap. JSON, pipes and `NO_COLOR` remain plain. The rejected interactive
  explorer and its third-party UI dependencies are not part of this release.
- Accumulated fixes to parsing/diagnostic boundaries, source retention, process
  cancellation/cleanup, Windows handle behavior and bounded storage walks; measured
  buffer/index/run reuse and persistence optimizations; expanded tests and fixtures.

The build manifest is **unsigned local provenance**, not a GitHub/Sigstore
attestation. Checksums detect changed bytes; they do not independently authenticate
a publisher. I am not claiming a signed release or independently reproduced build.
No repository protection, credential, signing key or Actions permission is changed.

## Verify and use

Obtain an archive, `SHA256SUMS` and `build-metadata.json` from the same tagged
GitHub prerelease. On Linux, from the download directory:

```bash
sha256sum --ignore-missing --check SHA256SUMS
tar -xzf packtrace_0.1.0-alpha.1_linux_amd64.tar.gz
./packtrace_0.1.0-alpha.1_linux_amd64/packtrace --version
```

Require the intended archive and manifest to report `OK`; a missing file was not
verified by `--ignore-missing`. On Windows, compare the downloaded ZIP and manifest
against the exact corresponding entries with PowerShell `Get-FileHash -Algorithm
SHA256`, then extract with the normal archive tool and run `packtrace.exe --version`.
Never run an unverified binary merely to obtain its version.

The expected application version is `0.1.0-alpha.1`, with an explicit experimental
warning. Operational report schema **1.7** is independent of the application version.

See the [English manual](../user-guide.md) / [manual en español](../user-guide.es.md)
for external policy/setup, offline scan, explicit data preparation and exit codes.
Archives contain neither live advisory data nor user configuration, credentials,
reference archives or investigated-project content. No suspicious package scripts
need to be executed to use the CLI.

## Known limitations

- Zero findings never certifies safety. Candidates are not confirmed vulnerabilities;
  missing/expired advisory data, unqualified origins, unsafe inputs and unsupported
  layouts remain visible gaps.
- Bun binary locks and npm lockfile v1/v4 are not newly admitted. The Bun1.2.23 local
  Git producer case remains unqualified; its captured non-Git subset does not erase
  that failure. Broad version ranges do not qualify every patch/layout/platform.
- Generic hardlink refusal remains intact. The explicitly selected Linux Bun-cache
  profile admits only a verified retained exactly-two-name manifest pair; three or
  more names remain refused. No implicit cache or credential discovery occurs.
- There is no automatic remediation or stable public Go API. CLI, display and
  internal contracts can change during the alpha series.
- This prerelease is published from its dedicated release branch. It does not imply
  integration into protected `development`, independent review, hosted final-head CI,
  a release qualification campaign or completion of the pre-1.0 shipping gates.
