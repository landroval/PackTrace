## New command and meaning

```text
packtrace --version
packtrace verify-integrity --help
packtrace verify-integrity --policy FILE --trusted-policy-digest SRI ROOT
```

`--version` identifies the experimental application, not a support guarantee.
`verify-integrity` is a separate **Linux-only, offline npm comparison**, requiring
an explicitly reviewed external version-1 policy and independently trusted
canonical SHA-256/384/512 SRI over its exact bytes. Do not regenerate a pin merely
to accept changed inputs. References are local, external to the target, and joined
to exact installed locations and lock claims. It does not use saved setup, run
advisory checks, emit JSON, install packages or execute target code.

- **0:** complete uniquely joined reference/content comparison, no drift.
- **1:** complete comparison with positive modified/missing/added/type drift.
- **3:** incomplete, including missing/unmapped/ambiguous ownership or references;
  takes precedence over drift. Missing inventory is not an empty scope.
- **2:** invalid input/pin or fatal acquisition/resource/output/finalization error.
- **130:** interruption. Precedence: `130 > 2 > 3 > 1 > 0`.

Equality does not establish benignness, publisher identity or independent
installation equality. Drift does not establish malware. Read the bilingual
[command contract and qualification boundaries](../verify-integrity.md), including
late errors after output, conservative ownership and bounded original gzip/USTAR
acceptance. Never truncate/repack an archive to make it pass. `scan` retains its
separate policy, coverage and enforcement gates.

## Accumulated changes since alpha.2

- Whole-installed integrity accounting, bounded compact npm original/reference
  tables, explicit scoped completion receipts and original-derived advisory
  snapshot completeness validation.
- Bounded pinned Bun origin/advisory grants and parent validation tied to retained
  original bytes; operational report **1.8** represents scoped coverage. Historical
  report contracts remain historical, not a way to import authority.
- Linux lifetime/finalization accounting and causal advisory regressions. These
  changes do not close every native/resource/lifecycle qualification gate.
- The explicit npm command selects `verify-npm-v2`, including bounded top-level
  envelope handling and independent validation of two historical TAR timestamp
  fields. Legacy `scan` archive acceptance and decision gates are not widened.
- **Intentional shared representation change:** distinct negative boundaries now
  use opaque `:boundary:N` evidence identities instead of potentially aliased
  `:nested`/`:unmapped` identities. Portable ordinals may change; legacy evidence
  is not byte-identical even where comparison decisions remain unchanged.
- Inherited partial pnpm format-9 recognition covers stable 9.x–12.x hints, with
  bounded active installed observations. Coverage remains incomplete, with no pnpm
  advisory lookup or integrity binding; mandatory gaps still exit 3. See the
  [version/layout matrix](../inventory-compatibility.md#pnpm-versionlayout-matrix).

this note makes no reused test-count, artifact or independent-reproduction claim.

Apache text, applicable pinned Go/SDK-vendored notices, and the existing advisory

rights to PackTrace itself; redistribution/modification rights remain unresolved
without an explicit rights-holder decision. No license or rights clearance is
invented here. Publication, tags/push, protected-branch integration and installation
