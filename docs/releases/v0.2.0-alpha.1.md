# PackTrace v0.2.0-alpha.1

I am publishing an **experimental prerelease** that groups the new pnpm capability
and accumulated safety/correctness fixes since [v0.1.0-alpha.1](v0.1.0-alpha.1.md).
The minor increment reflects functionality, not the number or size of commits;
see the [versioning policy](README.md). This is not production-qualified or full
pnpm support. Existing npm/Bun capabilities remain included.

## New capability: bounded pnpm FORMAT 9

- I add `pnpm-lock.yaml` format exactly **9.0** to the actual supervised `scan`,
  terminal, JSON and SARIF pipeline via `--manager pnpm` / `pnpm@lockfile-9`.
- I preserve manifest declarations, lockfile package/snapshot claims and observed
  installation separately. Peer contexts and aliases stay distinct; no lock key
  is a filesystem path or proof of installation or authenticated origin.
- I observe active contained installed slots only with stable single-link regular
  manifests. This means nlink=1, not one symlink hop. Store siblings require the
  exact `node_modules/.pnpm/<opaque>/node_modules` structure; orphan/nested orphan
  stores and target source/configuration are not read.
- I expose name/version correspondences only as **indeterminate candidates**, not
  physical lock joins, absence/conflict conclusions or unique peer bindings.
  Installed/reconciliation/workspace limitations remain mandatory and incomplete;
  pnpm scans normally return **3**. There is no pnpm advisory lookup, eligible
  finding, integrity binding or exception-authority expansion.
- I retain raw owned pnpm 9.15.9/10.34.9 lock and installed fixtures, including
  positive copy/peer cases and forced-hardlink rejection evidence. These exact
  producer anchors do not qualify every version, layout or platform.

## Accumulated fixes and dependency notices

- I bound repeated projected YAML strings as well as raw input, nodes, records and
  references, preventing snapshot fan-out from bypassing output budgets. Strict
  parsing rejects duplicate/complex keys, anchors, aliases, merge keys, explicit
  tags and extra documents instead of expanding them.
- I retain unsupported source IDs, importer references (including resolved peer
  references), root patch claims and unknown root semantics as explicit gaps.
- I require all three pnpm gaps in parent validation and bind candidate endpoints
  to selected-lock and native manifest/metadata witnesses. Older zero-observation
  reports remain valid; false completion/source substitutions are rejected.
- I prevent discarded physical-link edges from consuming candidate budgets.
  A late ancestor-lease failure invalidates visited descendant evidence in the
  shared installed walker, preserving npm/Bun safety too.
- I update current English/Spanish manuals and correct the producer-runtime prose
  label to the exact Node v26.13.1 recorded in the retained receipts.
- I pin and vendor `go.yaml.in/yaml/v3 v3.0.6`. Its MIT and Apache-2.0 portions,
  original LICENSE/NOTICE and complete Apache text are retained in both archives,
  separately from Go/stdlib notices. This is not a choice of either license for
  the entire YAML dependency. No pnpm runtime or new project license is bundled.

## Verify and use

Obtain the intended archive, `SHA256SUMS` and `build-metadata.json` from the same
GitHub prerelease. On Linux, in the download directory:

```bash
sha256sum --ignore-missing --check SHA256SUMS
tar -xzf packtrace_0.2.0-alpha.1_linux_amd64.tar.gz
./packtrace_0.2.0-alpha.1_linux_amd64/packtrace --version
```

Require the intended archive and build manifest to report `OK`; a missing file is
not verified by `--ignore-missing`. On Windows, compare the exact ZIP and manifest
entries with PowerShell `Get-FileHash -Algorithm SHA256`, then extract normally.
Do not execute an unverified file just to obtain its version. Expected output is
`packtrace 0.2.0-alpha.1 (experimental; not production-qualified)`.

Operational report schema **1.7** is unchanged and independent of this application
version. See the [English manual](../user-guide.md) / [manual en español](../user-guide.es.md)
for external policy, setup, offline scan and exit precedence. Archives do not
install services, change configuration, download intelligence or execute target
scripts. Installing a new executable does not repin saved policies or authorize
new target/source access. Zero findings never certifies safety.

## Remaining gates

Full pnpm workspaces, external/shared stores, generic hardlinks, catalogs, patches,
binary Bun locks, Yarn and pnpm advisory/integrity authority are not newly admitted.
Generic hardlink refusal remains intact; the existing explicit Linux Bun-cache
exactly-two-name allowance is unchanged and is not a pnpm permission. Source
currentness, eligibility and platform qualification remain separate gates.

I publish from a dedicated release branch/tag. Publication does not itself merge
version changes into protected `development`, imply human review, complete native
release qualification or satisfy the pre-1.0 shipping gates. No protections,
credentials, signing keys or Actions permissions are changed.
